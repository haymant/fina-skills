# RiskCube columnar storage and OLAP

## Non-negotiable storage rule

Do not store generated sensitivities, P&L, Taylor terms, or forecasts in JSON. Write typed rows to Parquet and query them through DuckDB. JSON manifests may describe schema, provenance, and locations only.

## Hive layout

Use Hive partitioning with stable pruning keys first:

```text
<root>/dataset_id=<dataset>/version_key=<version>/scenario_key=<scenario>/report_kind=<kind>/as_of_date=<YYYY-MM-DD>/part-*.parquet
```

The exact root may be local, S3, or GCS, but the partition columns and names are stable. Do not partition by high-cardinality RFK axes. Keep `instance_id` and `report_key` as columns; add them to the path only when operationally useful.

## Row contract

The composite primary key is the normalized RFK tuple plus report execution identity:

```text
(report_key, version_key, scenario_key, instance_id,
 instrument_id, portfolio_id, rfk_type, rfk_underlying,
 rfk_currency_pair, rfk_curve, rfk_expiry, rfk_strike,
 rfk_tenor, rfk_temporal_role, rfk_date, rfk_surface_parameter)
```

A dataset may omit an axis only when its manifest declares the omission and uniqueness remains provable. Use stable snake_case columns, explicit numeric types, UTC timestamps, and nullable typed values. Include `row_hash` or a manifest checksum for integrity.

## fina-olap integration

For `/riskcube/cube`, call the **fina-olap stdio MCP server** from a server-side adapter. Use its SSRM-shaped query contract so the same request supports sorting, filtering, grouping, pivoting, aggregation, pagination, and export. The adapter must pass the resolved Parquet root/glob and `hivePartitioning: true`, enforce an allowlisted table/report view, and bind user filters as structured values rather than interpolated SQL.

The server returns rows, `lastRow`, columns/metadata, and provenance. The page renders these through the `fina-table` React component. Keep the table data source, query mapper, value formatters, grouping/pivot panel, and report controls separately testable. Do not make the browser aware of DuckDB paths or MCP command details.

## Query safety and reproducibility

Only allow dimensions and measures declared by the report manifest. Validate aggregation compatibility and reject unregistered columns. Record the report key, version/scenario filters, SSRM request, resolved source, partition columns, engine version, and materialization time with exports and audit events.

Typical query shape:

```sql
SELECT scenario_key, instrument_id, rfk_type, rfk_underlying,
       SUM(pv_amount) AS pv_amount,
       SUM(delta) AS delta,
       SUM(taylor_1) AS taylor_1
FROM read_parquet('<root>/dataset_id=*/version_key=*/scenario_key=*/report_kind=*/as_of_date=*/*.parquet', hive_partitioning=true)
WHERE version_key = ? AND scenario_key IN (?, ?)
GROUP BY ALL
```

Use DuckDB SQL generated by fina-olap; do not execute arbitrary SQL from UI input.
